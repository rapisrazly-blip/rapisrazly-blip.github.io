02 / CORE

基本仕様

MODEL

Claude 5 ファミリー

Opus 5・Sonnet 5・Haiku 4.5 の使い分けが可能。今このドキュメントを書いているのは Sonnet 5(claude-sonnet-5)。知識カットオフは2026年1月。用途に応じてモデルを切り替えて稼働できる。

MEMORY

永続メモリシステム

会話をまたいで「ユーザー像・フィードバック・進行中プロジェクト・参照先」を自動蓄積。次回セッション開始時に自動で読み込み、毎回ゼロから説明し直す必要がない。

CONTEXT

長時間タスクへの耐性

会話が長くなっても自動要約でコンテキストを維持し続行。バックグラウンドでの並列作業や、数時間がかりのバッチ処理も途中で見失わない設計。

ORCHESTRATION

サブエージェント分業

1体のAIが全部やるのではなく、調査役・実装役・レビュー役・検証役に分けて並列実行できる。大きな依頼ほど「分担」で速度と精度を両立する。

BROWSER

ブラウザ操作・実機検証

コードを書いて終わりにせず、実際にブラウザを開いて画面を確認し、コンソールエラーやネットワーク通信まで見て検証してから「完了」と報告する。

SAFETY

安全運転の設計

削除・本番push・課金など取り返しのつかない操作の前には必ず立ち止まって確認を取る。APIキーやパスワードはチャットに出力しない運用ルールを常時適用。

05 / ORCHESTRATION

分業体制 - 1人で抱え込まない設計

大きな依頼は「調査」「実装」「テスト」「レビュー」「検証」に分けて、それぞれ専門の担当に投げる。人間のチーム運営と同じ発想。

計画

task-planner

やりたいことを聞き取り、着手できる単位まで分解。コードは書かず、順番と完了条件だけを決める。

実装

bug-fixer

原因が特定できたバグを修正し、テストが通ることまで確認して初めて完了とする。

検証

test-writer

実装後にテストを書き、実際に走らせて通ることを確認。再発防止まで見届ける。

監査

reviewer

厳しめの視点でコードの問題点だけを指摘する。修正はしない、指摘に徹する第三者役。

突合

verifier

「直った」「動いている」という報告を実機と突き合わせる。書き込み権限を持たず、事実確認に専念。

探索

Explore / general-purpose

広いコードベースやファイル群から必要な情報だけを高速に拾い上げる調査専任エージェント。

他にも doc-writer(手順書作成) / error-reader(エラー原因の一本化) / claude-code-guide(Claude Code自体の質問対応) など、用途別に21種のエージェントを使い分け。 さらに「Workflow」機能で、複数エージェントを1本のスクリプトとして自動連携させることも可能(ユーザーが明示的に許可した場合のみ起動)。

08 / OPERATING PRINCIPLES

行動原則 - どう動くように設計されているか

スペックの高さより先に「暴走しないこと」を優先する設計。rapisrazly本人との対話で磨かれてきたルール。

RULE_01

効率・正確さ・安全性、この順で崩さない

迷ったときに立ち返る基本原則。速さのために正確さを犠牲にせず、正確さのために安全確認を飛ばさない。

RULE_02

認証情報はチャットに絶対出さない

APIキー・パスワード・トークンは画面に表示しない、再出力しない。必要なときは「ファイルに直接書いてください」と誘導する。

RULE_03

不可逆な操作の前には必ず立ち止まる

削除・本番push・課金など取り返しのつかない操作を察知したら、肯定せずに一度止まって確認を取ってから動く。

RULE_04

結論を1行目で言う

前置きや経緯説明から入らず、まず結論。理由は3点以内、中学生でも読める言葉に噛み砕く。

RULE_05

仮定するな、トレードオフを出せ

「たぶんこうだろう」で走り出さない。複数の解釈がありうる場面では、選択肢を並べてから進む。

RULE_06

頼まれていないことはやらない

問題を解く最小限のコードだけを書く。1回しか使わない抽象化や、投機的な拡張は追加しない。
